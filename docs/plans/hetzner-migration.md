# Tallaby: Vercel → Hetzner + Cloudflare migration plan

Status: **Planned** (owner idea, 2026-11-19). Nothing below is built except §1.
Goal: run every Tallaby app on Hetzner (Coolify, Docker) to cut hosting cost, with Cloudflare for DNS, SSL, CDN and WAF. Supabase (DB, Auth, Storage), Resend, payment gateways and other external APIs stay where they are. The database does **not** move to the VPS.

This is a hosting change, not a business-model change, but it touches checkout, payments callbacks, crons that move money (`tallaby-pay-release`, `cod-deposits`, `plan-renewals`) and tenant routing, so CLAUDE.md rules 3, 5, 7, 8 and 10 apply to every step.

## 4. Server

- **Size:** CX23 (4 GB) is too small for 5–6 Node apps plus Coolify. Start at **CX33/CX43** and measure. Never build on the production VPS: build in CI.
- **Location:** next to the Supabase region (Falkenstein or Nuremberg for Frankfurt). Every DB query crosses that link; it matters more than distance to Egypt.
- **Reliability (one VPS = one point of failure):** Coolify health checks and zero-downtime deploys, Hetzner backups/snapshots, uptime alerts, unattended security updates, SSH keys only, Hetzner firewall allowing 80/443 from Cloudflare only and 22 from our IPs. Later: a second VPS behind a Hetzner load balancer (needs the shared cache from §2).
- **Secrets:** Coolify env only (rule 10). `NEXT_PUBLIC_*` are build-time, so they are build args per app image.

## 5. Cloudflare after an app moves (orange cloud)

- SSL **Full (strict)** with a Cloudflare Origin CA wildcard cert (`tallaby.com`, `*.tallaby.com`) on the VPS proxy. Universal SSL already covers both names.
- Remove the `_acme-challenge` NS delegation to Vercel once nothing on `*.tallaby.com` is served by Vercel.
- **Cache only static assets.** No "Cache Everything" on HTML: carts, orders, wallets, builder drafts and dashboards must never be cached (rule 8).
- **WAF skip rules** for every machine caller: EasyKash, Kashier, Paymob callbacks; Bosta; Supabase database webhooks (`/api/cron/seller-push`, admin `/api/cron/admin-push`); cron routes; MCP and OAuth (`/oauth/*`, `/api/oauth/*`, `/.well-known/*`, `/mcp`). Keep **Bot Fight Mode off** (Free plan cannot exempt paths).
- Rate-limit rules on login, checkout and OTP endpoints.
- **`TRUST_CLOUDFLARE_HEADERS=1`** (runtime env, per app): set it only once that host's Cloudflare proxy is on AND the Hetzner firewall allows 80/443 only from Cloudflare's IP ranges. Then `@workspace/lib/http/client-ip` (`getClientIp`, `getClientCountry`) reads `CF-Connecting-IP` and `CF-IPCountry` (`XX`/`T1` = no country). Unset (Vercel, grey-cloud hosts) those headers are ignored, so a client cannot forge them, and the helper returns what the call sites read before (first `x-forwarded-for` entry, then `x-real-ip`; `x-vercel-ip-country`).

### Done 2026-11-19 (admin, deploy, api, mcp)

- **Edge certificate:** Cloudflare Universal SSL (`tallaby.com`, `*.tallaby.com`, Let's Encrypt, active 03:05Z, renews about every 90 days). It validates by TXT at `_acme-challenge.tallaby.com`, which is NS-delegated to Vercel DNS for Vercel's wildcard renewals, so **Cloudflare's two TXT values were added to Vercel's DNS zone** (records `_acme-challenge`, comment "Cloudflare Universal SSL validation"). On each Cloudflare renewal, new TXT values must be added there until the delegation is removed (when no `*.tallaby.com` store is served by Vercel). The first proxy attempt (02:0xZ) failed TLS at the edge for ~2 minutes because the certificate was still pending; check `ssl/certificate_packs` is `active` before proxying a host.
- **Origin certificates:** the server keeps its own Let's Encrypt certificates (Full (strict) works with them, no Origin CA needed). Zone "Always use HTTPS" is **off** so port-80 ACME challenges reach Traefik through Cloudflare; Traefik itself redirects HTTP to HTTPS (checked: `/login` 302, `/.well-known/acme-challenge/*` reaches Traefik).
- **Zone settings:** SSL Full (strict), minimum TLS 1.2, Bot Fight Mode off.
- **Configuration rule:** `api.tallaby.com`, `mcp.tallaby.com` → Browser Integrity Check off, security level "essentially off" (webhook senders and MCP agents; tested with an empty User-Agent).
- **Rate limit:** `admin.tallaby.com` `POST /login` max 10 per 10 s per IP (block 10 s; Free plan limits).
- **Proxied (orange):** `admin`, `deploy`, `api`, `mcp`. **Hetzner firewall:** 80/443 only from Cloudflare's 15 IPv4 + 7 IPv6 ranges (from `GET /ips`; update if Cloudflare changes them), 22 and ICMP open; direct HTTP(S) to 2.28.78.10 times out.
- **`TRUST_CLOUDFLARE_HEADERS=1`** on Coolify apps `tallaby-admin` and `tallaby-backend`.
- Any new app on this server must be proxied before it can be reached (the firewall now blocks direct access).

### 7.2 TLS and seller domains: options

| | A. Cloudflare all the way (**recommended**) | B. Open the firewall, certs on the server (Caddy on-demand, or Traefik + one router per domain) | C. Hybrid: subdomains to Hetzner, custom domains stay on Vercel |
| --- | --- | --- | --- |
| `*.tallaby.com` | proxied `*` → VPS; edge cert = Universal SSL (already covers `*.tallaby.com`); origin cert = **Cloudflare Origin CA** `tallaby.com` + `*.tallaby.com` (free, up to 15 years, Full strict OK) loaded as Traefik's default cert | same as A | same as A |
| Seller domains | **Cloudflare for SaaS** custom hostnames (Free plan: 100 hostnames included, then $0.10/hostname/month; apex + www = 2). Seller CNAMEs `www` to our fallback origin (e.g. `shops.tallaby.com`); cert issued by Cloudflare (HTTP DCV), can be **pre-validated by TXT** before the seller changes DNS | seller A record → VPS public IP; Let's Encrypt per domain (HTTP-01) | stay on Vercel until later |
| Origin firewall | stays Cloudflare-only (everything arrives through the edge) | 80/443 open to the world: DDoS straight to the VPS, IP becomes public and fixed (a server move breaks every seller) | stays |
| Apex domains | **Free plan has no apex A records** (Enterprise add-on): seller needs ALIAS/CNAME flattening at their DNS host, or forwards the apex to `www` | plain A record works | as today |
| Cost / ops | $0 for ≤ 50 domains; Cloudflare manages certs | rate limits (LE), Caddy `ask` endpoint can take sites down | keeps paying Vercel; two copies of the app, caches can go stale between them (broadcast has one ecommerce peer) |

**Recommendation: A.** It keeps the origin locked, sellers never see an IP, and the server can be replaced freely. B is rejected for the open firewall. C is fine only as a short transition (step 7.5 runs subdomains first, custom domains a few days later).

Open technical points to prove on one hostname before rollout: (1) with Full (strict), Cloudflare sends the seller's hostname as SNI; Traefik answers with the default Origin CA cert, which does not name it. If Cloudflare rejects that, add a Configuration Rule "SSL: Full" for hosts outside `tallaby.com` (the firewall still keeps the origin Cloudflare-only); consider Authenticated Origin Pulls so only our zone's traffic is accepted. (2) The catch-all Traefik router must answer unknown hosts (custom hostnames), and the app's proxy already 404s hosts it does not know.
