Every label in the video is the string from `ar.json`. The chooser page and the products list use the same rebuilt layout as T-01.

**What the code does (and its limits):**

- **Files accepted:** `.xlsx`, `.xls`, `.csv`, `.tsv` and `.pdf` (`ACCEPTED_FILE_TYPES`). The page's own line says "CSV أو XLSX أو TSV، أو كتالوج PDF حتى 20 صفحة". The video uploads an Excel file, and the voice says only "ملف الإكسل".
- **Limits (`BULK_LIMITS`):** 5 MB a file, 500 products a file, 20 pages for a PDF, 40 columns, 3 photos a product (from links in the file). A file with several sheets: only the first sheet with data is read.
- **AI:** the page uses AI to match the columns when it does not know their names, to read a PDF catalogue, and to write the Arabic and English name and description of each product that lacks them. Each such product uses 1 AI credit (`BULK_CREDITS_PER_AI_PRODUCT`); the Free plan has 100 credits a month. There are also daily caps (copy 100 calls, column matching 20, PDF 40 by default; 10 times that on Pro). When credits or the daily cap run out, the page keeps what was added and offers to continue. The video shows the normal state: 6 products, 6 credits, balance 100. The voice says nothing about AI.
- **Published or draft:** a row with a photo link, a quantity, a normal name and a sure category is published at once; the others are saved as hidden drafts. In the video all six rows are complete, so all six are published ("منشورة الآن 6"). The closing line says the products "were added to your store", which is true in both cases.
- **No review per product:** the confirm screen shows counts and the first five rows only; pressing "إضافة جميع المنتجات" adds every valid row.
- All six rows are sent in one batch (batch size 10), so the real progress line stays at "اكتمل 0 من 6" and 0% until the batch returns, then the done card appears. The video shows it that way.

**Where the real page differs from the outline in TUTORIALS.md §11** ("Upload the file → check the rows → import → the products list"):

- The seller reaches the page from the choice of four methods, so step 1 is choosing "رفع ملف منتجات" (the route itself is still `/stores/[storeId]/products/add/from-file`).
- "Check the rows" is one confirm screen, "راجع قبل الإضافة": four counts, an AI credit estimate, a folded "محتوى كل عمود" (the column mapping) and the first five rows. There is no row-by-row editing.
- The import button is "إضافة جميع المنتجات (6)".
- After the import the page does **not** go to the products list by itself. It shows the done card with "عرض المنتجات", so pressing it is step 5. The products list shows no success message after this (it is a plain link), so the result has no toast.

**Simplified or not shown:**

- "تحميل نموذج الملف", the "×" on the file row, "استخدام ملف آخر" and the folded "محتوى كل عمود" are drawn from the code but are not used.
- The reading stage is shortened to about 1.7 s and the adding stage to 1.6 s. Real ones take longer (AI calls, photo downloads).
- On the real phone layout the page's content is centred in the screen on the first (pick) stage; here it starts under the back bar.
- The chooser cards and the list are scrolled so the thing being used sits in the safe area; extra empty room under the page content exists only for that.
