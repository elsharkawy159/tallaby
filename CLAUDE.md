## Durable rules

1. **Check the code before trusting a doc.** Re-read the files a task touches. Never treat a "Planned" item in `PLAN.md` as already built.
2. **Follow `PLAN.md` task order.** After each task, update its checklist (§22), the log (§23) and any note about where the code differed from the plan.
3. **Keep existing behaviour.** The marketplace, checkout (`packages/lib/src/orders/place-order.ts`), wallets (`docs/wallet.md`), shipping and fulfillment (`docs/fulfillment.md`) must keep working. Make small changes, not rewrites.
4. **Stop and ask** before changing the agreed business model (`PLAN.md` §13), running a destructive or production migration, or changing money and ledger logic outside an approved task.
5. **Tenant isolation.** The `sellers` row (`sellers.id = users.id`) is the **account** (plan, wallet, trial, legal data). The planned **`stores`** table is the **tenant**: a seller can own several stores, up to the plan limit (Free = 3; `sellers.plan` defaults to `'free'`, and limits live in the code plans module). Server code bypasses RLS through Drizzle, so every query must check that the store belongs to the session's seller and filter child rows by `store_id`. On storefronts, the store comes from the request host. Store-scoped actions always take an explicit `storeId`; never use a "current store" cookie as the target of a write. Never trust seller or store IDs sent by the client. Hiding a UI element is not authorization.
6. **Migrations.**
   - Write hand-written, idempotent SQL in `packages/db/migrations/NNNN_name.sql` (next number: `0085`; `0084` re-seeds every template (Classic v4, the others v2) with no header padding-y on mobile, on staging and production 2026-10-20, and the seed tests check it; `0083` seeds the Automotive library templates Garage, Drive and Moto, `0082` seeds the Sports library templates Pace, Stride, Core and Basecamp, `0081` seeds the Kids library templates Playroom, Bambino, Doodle and Hekaya, `0080` the Jewelry library templates Lumière, Karat and Fadda, `0079` the Furniture library templates Verdant, Loft, Oak and Sakan, `0078` the Food library templates Sizzle, Harvest, Loaf and Roast, `0077` the Home & Kitchen library templates Nest, Daily, Hearth and Clay, `0076` the Beauty library templates Pure, Glow, Élixir and Botanica, `0075` the Electronics library templates TechHub, Volt, Arcade and Arena, `0074` the Fashion ones Mode, Streetwear and Kasr (staging and production 2026-10-20); `0073` adds `platform_blog_posts`, the `platform-blog` bucket and `is_platform_admin()` for the admin-written tallaby.com blog; `0072` adds `newsletter_subscribers` for the tallaby.com blog newsletter; `0071` seeds Tallaby Classic v3 (tree sections) as the default template, generated by `template:sql`; `0070` seeds the Atelier storefront template, generated by `template:sql`; `0069` makes `admin_audit_log.seller_id` nullable for platform rows; `0068` adds the per-seller category and brand lists; `0067` is the flat EGP 5 fee and 7-day trial; `0049` is the 2026-10-17 RLS security fix. **`0049`–`0073` are applied on staging and production (2026-10-20, `PLAN.md` §23); a new migration goes to staging first, then production with owner approval. Never re-run `0050` after `0065`;** `0065` drops `stores.policies`, `0066` adds the private `store-top-up-proofs` bucket).
   - Mirror each change in `packages/db/src/drizzle/schema.ts` and `relations.ts`.
   - **Do not run `drizzle-kit generate`.** Its journal stops at `0033`.
   - New server-only tables get RLS enabled with no policies.
7. **Money.** Compute in integer piastres and store in the existing `numeric(10,2)` columns. Ledger writes must be idempotent, using a unique claim plus `ON CONFLICT`. Store-wallet balances (seller ledger) change **only** through the planned `postStoreWalletEntry` primitive. Store wallets may be negative, customer `user_wallets` may not, and the two ledgers stay separate. The agreed fee is a flat EGP 5 per seller per delivered order, taken from the store wallet (which may go negative), with a 7-day free trial counted from the seller's first store `created_at` (`PLAN.md` §13, 0067).
8. **Caching.** Use `@workspace/cache` (`createCachedQuery`, tags in `packages/cache/src/tags.ts`, cross-app broadcast). Never cache carts, orders, wallets, builder drafts or integration secrets. Every cache key and tag for store data includes the seller ID.
9. **No seller-supplied code.** The builder has no custom HTML or JS nodes. Integrations inject scripts only from fixed templates, with IDs checked by regex, and only on that seller's storefront host.
10. **Secrets.** Never put secrets in `NEXT_PUBLIC_*`, client components, logs or docs. The service-role key stays in server code only.
11. **Reference builder is read-only.** The reference is Valorcy (the owner's project, GitHub `elsharkawy159/saas`) at `D:\programming projects\saas\apps\dashboard`. It covers the builder, forms, templates/themes and media library. Never modify it, or any other reference project. The copied Valorcy code in `apps/dashboard` (`app/(builder)`, `components/{cms,design,dnd,navigation,sections,website,website-builder,websites}`) was untracked user work at planning time. Do not delete it. `PLAN.md` P0-02 explains how to quarantine it.
12. **Default storefront.** Tallaby Classic is the default template again, rebuilt as tree sections (owner, 2026-10-19; `packages/store-sections/src/templates/classic/`, key `tallaby-classic`, v3 in `0071`). A never-published store gets it in its builder DRAFTS when its site scaffold is made (`ensureStoreSiteScaffold` → `seedStarterSite`), with its newsletter and contact forms, its name and its default language; the live site changes only on Publish. The storefront fallback for stores without a published builder site (`apps/ecommerce/app/[locale]/(shop)/storefront/[subdomain]/page.tsx`) still draws hero, categories and catalog; keep how it looks. Do not change the default template's design without the owner's approval.
17. **Sections are element trees.** Every website section and template is built as an element tree with `defineDesign` (`packages/store-sections/src/designs/<library-category>/<id>.ts`) and inserted as a `custom-section` whose single root is a `section` node, so every element can be selected, styled and moved (owner, 2026-10-19). Never write a coded `SectionDefinition` + `Component` section. Follow the authoring rules in `docs/superpowers/specs/2026-10-19-tree-sections-design.md` §6, and add each new design id to `EXPECTED` in `designs/designs.test.tsx`.
13. **i18n.** Arabic is the default locale. Add every string to both `ar.json` and `en.json`. The Arabic brand name is **طلبي**.
14. **Code organisation.** Use the feature file split (`*.server.ts`, `*.data.tsx`, `*.client.tsx`, `*.dto.ts`, `*.types.ts`, `*.lib.ts`). Do not add to `apps/dashboard/actions/products.ts`.
15. **Verification.** Run `pnpm lint`, `pnpm typecheck` and `pnpm test` (or the `--filter` equivalents) after each task. DB integration tests run only when `TEST_DATABASE_URL` is set. There is no E2E runner or CI yet, so record manual E2E checks in `PLAN.md` §23.
16. **Do not touch others' uncommitted work.** Check `git status` first. Never discard or overwrite changes you did not make.
